# 06 | Drive Manager and Platform Installation Design

## Storage concepts
A physical disk may contain multiple partitions, volumes and mount points. A mounted drive letter is not necessarily the underlying disk. The app must model these separately before any format, imaging or clone feature is implemented.

## Read-only discovery (phase 1)
Enumerate mounted storage; display OS-reported capacity/free space, filesystem type, mount point, and disk identity when available. Clearly flag system volumes and inaccessible/unknown devices. Do not probe unknown raw devices with writes.

## Installation types
- **Batocera:** bootable operating system with platform/hardware-specific image and userdata layout. On Windows, direct access to Linux data partitions may not be supported; consider the Batocera network share after first boot, or an explicitly designed trusted access mechanism. Do not assume raw FAT/NTFS game paths are universally writable.
  - **Implemented read-only (RDS-008, 2026-11-06, `src-tauri/src/adapters/batocera.rs`; facts checked against the Batocera wiki and source):**
    - **Where games are:** the **BATOCERA** partition is the system (`batocera-boot.conf`, `boot\batocera`) and the only one Windows sees by default; games never go there. Games live on **SHARE** ("userdata"), ext4 by default, which Windows can't read. From Windows, the game folder is either the network share **`\\BATOCERA\share`** (while Batocera runs) or, when an external drive is used for storage, the **`batocera` folder at that drive's root** (exFAT/NTFS are readable).
    - **Detection:** "Detected" needs `roms\` plus `system\batocera.conf` (Batocera creates both on every boot if missing). A folder with `RetroBat.exe` is never claimed. Near misses are "Possible" (never saved) with a hint: the boot partition (choose the game folder instead), a drive root with a `batocera` folder (choose that folder), or userdata folders without `batocera.conf` (start Batocera once).
    - **Layout checks:** `roms`, `bios`, `system\batocera.conf`, access (network share or local drive), copying (not yet) and version.
    - **Version:** unknown. It isn't on SHARE and is inside the system image on the boot partition.
    - **Folder mapping:** the same as RetroBat (every folder RetroDrive uses exists in Batocera's `es_systems.yml`), except **CPS1/2/3**, which Batocera has no folders for: they follow the installation's arcade choice (`roms\mame` or `roms\fbneo`).
    - **Copying (RDS-022, 2026-11-07, docs/18 §21):** on by owner approval ("Yes, start step 1"). Same copier as RetroBat (verified copies, no overwrite, Replace backs up, journal and recovery), to a game drive plugged into this PC (`<drive>\batocera`, exFAT or NTFS) or over `\\BATOCERA\share`. A network share is identified by the id RetroDrive leaves in `<share>\.retrodrive\share-id` on its first copy (ADR-046); a different machine answering to the same name shows as *a different drive* and is never copied to. The layout check *Copying* is OK for a drive and a warning ("keep Batocera on…") for the share; the confirm box says so too. Sync, art and details for Batocera are the next step.
    - **Sync, art and details (step 2, 2026-11-07, ADR-047):** the Batocera card has **Sync** (same sync scope as RetroBat). Art and details go into Batocera's `roms\<system>\gamelist.xml` with images in `roms\<system>\images\` (the same convention as RetroBat), when copying or from Customize, undoable. Batocera runs on its own machine, so there's no "close it first" check; a running Batocera shows the new art after **Start → Game Settings → Update Gamelists** (Batocera wiki, add_games_bios), which RetroDrive says after adding art. Emulator settings and themes stay RetroBat-only until RDS-024.
    - **Settings and theme (step 3, 2026-11-07, ADR-048):** `system\batocera.conf` (`global.<key>` / `<system>.<key>`; Batocera's own option values from `_shared.emulator.yml`) and `ThemeSet` in `system\configs\emulationstation\es_settings.cfg`. Edits mirror Batocera's menu (re-read, change only those lines), so they're safe while Batocera runs; a theme switch over the network should be followed by a restart before other menu changes (Batocera rewrites es_settings.cfg on quit when a menu setting changed).
    - **Sources:** https://wiki.batocera.org/batocera.linux_architecture, https://wiki.batocera.org/add_games_bios, https://wiki.batocera.org/store_games_on_a_second_usb_sata_drive, and in https://github.com/batocera-linux/batocera.linux: `board/batocera/fsoverlay/etc/init.d/S11share` and `S12populateshare`, `board/batocera/scripts/post-image-script.sh`, `package/batocera/emulationstation/batocera-es-system/es_systems.yml` (checked 2026-11-06).
- **RetroBat:** portable Windows application/frontend with its own directory layout. First support placement to a normal user-selected writable folder; preserve app layout and upstream distribution rules.
  - **Implemented read-only (RDS-007, facts verified 2026-11-04 against the RetroBat wiki):**
    - **Detection:** "Detected" needs `RetroBat.exe` plus at least one of `emulationstation\`, `retrobat.ini` or `roms\`. Without the exe it can only be "Possible", which is never saved. A fresh install has no `retrobat.ini` until RetroBat first runs (observed on 8.3.1.1).
    - **Layout checks:** `roms`, `bios`, `emulators` and `emulationstation` folders, plus the install path (the wiki advises against spaces, accents and drive roots).
    - **Version:** read from `system\version.info` (fallback `emulationstation\version.info`), e.g. `8.3.1.1-stable-win64`. Not documented by RetroBat; observed on a real 8.3.1.1 install on 2026-11-05 (`RetroBat.exe` still reports 8.3.0.0, so it isn't used). Only a short version-like string is accepted.
    - **Folder mapping:** NES→`nes` (`.fds`→`fds`), SNES→`snes`, Genesis→`megadrive`, Master System→`mastersystem`, Game Gear→`gamegear`, PlayStation→`psx`, PS2→`ps2`, Game Boy→`gb`, GBC→`gbc`, GBA→`gba`, N64→`n64`.
    - **More systems (2026-11-05, checked against the RetroBat supported-systems page):** Famicom Disk System→`fds`, Amstrad CPC→`amstradcpc`, GX4000→`gx4000`, Atari 800→`atari800`, Atari ST→`atarist`, Atari 2600/5200/7800→`atari2600`/`atari5200`/`atari7800`, Lynx→`lynx`, Jaguar→`jaguar`, C64→`c64`, Amiga→`amiga500`, Amiga 1200→`amiga1200`, CD32→`amigacd32`, X68000→`x68000`, MSX→`msx1`, MSX2→`msx2`, ZX81→`zx81`, ZX Spectrum→`zxspectrum`, PC Engine→`pcengine`, PC Engine CD→`pcenginecd`, SuperGrafx→`supergrafx`, DS→`nds`, Neo Geo→`neogeo`, Neo Geo CD→`neogeocd`, NGP/NGPC→`ngp`/`ngpc`, Intellivision→`intellivision`, SG-1000→`sg1000`, Odyssey 2→`odyssey2`, WonderSwan/Color→`wswan`/`wswanc`, ColecoVision→`colecovision`, Vectrex→`vectrex`, Game & Watch→`gameandwatch`, 32X→`sega32x`, Sega CD→`megacd`, Pokemon Mini→`pokemini`, Virtual Boy→`virtualboy`, Supervision→`supervision`, CPS1/2/3→`cps1`/`cps2`/`cps3`, Dreamcast→`dreamcast`, Naomi→`naomi`, Atomiswave→`atomiswave`, Saturn→`saturn`, 3DO→`3do`. **BIOS files are never placed.**
    - **Arcade:** never guessed. Each installation has a setting, *Arcade games go to*: not chosen (default; arcade games aren't placed), **MAME** (`roms\mame`) or **FinalBurn Neo** (`roms\fbneo`). Only `.zip`/`.7z` archives are placed, with their names unchanged (they are romset names). CHD disks aren't placed yet: they must sit in a folder named after their game's zip. Per the RetroBat Arcade Guide, romset versions must match the emulator, non-merged sets are recommended and merged sets aren't supported.
    - **Multi-file games** go to `roms\<system>\<Game title>\…`, keeping file paths relative to the playlist or cue sheet.
    - **Emulator settings (RDS-021 v1, 2026-11-06):** RetroBat keeps menu choices in `emulationstation\.emulationstation\es_settings.cfg` as `<string name="<system>.<key>" value="…" />` and writes them into each emulator's config at every launch (wiki: configuration of systems and games). Its launcher reads every element's `name`/`value` and applies global, then `<system>.`, then per-game keys (`emulatorLauncher/Program.cs`, `ConfigFile.cs` in RetroBat-Official/emulatorlauncher). Keys used: `emulator`, `core`, `shaderset`, `bezel`, `ratio`, `integerscale`; a missing key is AUTO. Choices: emulators/cores from `es_systems.cfg`, ratios from the `ratio` feature in `es_features.cfg`, shader sets from `system\shaders\configs\<name>`, bezels from `system\decorations` and `decorations`. Checked on the owner's RetroBat 8.3.1.1 (read only): 244 systems, 25 ratios.
    - **Sources:** https://wiki.retrobat.org/get-started/retrobat-folder-structure, https://wiki.retrobat.org/get-started/installation-and-first-startup and https://wiki.retrobat.org/systems-and-emulators/supported-game-systems and https://wiki.retrobat.org/systems-and-emulators/arcade-guide (checked 2026-11-05).
- **ES-DE/EmulationStation:** frontend, not interchangeable with a bootable OS image.
- **retrobat.ini (2026-11-06, checked on the owner's RetroBat 8.3.1.1, read only):** an INI file whose own comments document each key. `[SplashScreen]`: `EnableIntro`, `FileName` (used when `RandomVideo=0`), `FilePath` (`default` = `emulationstation\.emulationstation\video`), `RandomVideo`, `VideoDelay`, `WaitForVideoEnd`, `KillVideoWhenESReady`, `GamepadVideoKill`. `[EmulationStation]`: `Fullscreen`, `FullscreenBorderless`, `InterfaceMode` (0 normal, 1 kiosk, 2 kid), `RandomTheme`, `NoExitMenu`, `VSync`, `DrawFramerate` and others. `[RetroBat]`: `LanguageDetection`, `DisableWindowsInterface`, plus `Autostart`, `ResetConfigMode`, `AppLauncher` (deliberately not offered). Menu music is the folder `emulationstation\.emulationstation\music` (.ogg files on the owner's install).
- **Menu music settings (2026-11-06):** in es_settings.cfg, read by RetroBat's EmulationStation (the names are present in the owner's `emulationstation.exe`; behaviour from batocera-emulationstation's `Settings.cpp`/`AudioManager.cpp`): `audio.bgmusic` (bool, default on), `audio.persystem` (bool: play music from `music\<system>` folders for the system being browsed), `audio.thememusics` (bool: theme-provided music), `audio.display_titles` (bool) and `audio.display_titles_time` (int, seconds), `MusicVolume` (int, default 128), `StopMusicOnScreenSaver` (bool), `VideoLowersMusic` (bool). Bool and int settings must be written as `<bool>`/`<int>` elements.
- **RetroBat game lists (2026-11-07, checked on the owner's RetroBat):** `roms\<system>\gamelist.xml`, root `<gameList>`, one `<game>` per ROM with `<path>./<file></path>`, `<name>`, `<image>`, `<thumbnail>`, `<marquee>` (paths relative to the system folder, usually `./images/<stem>-image.png` / `-thumb` / `-marquee`), `<desc>`, `<releasedate>YYYYMMDDT000000</releasedate>`, `<developer>`, `<publisher>`, `<genre>`. RetroBat rewrites the file when it exits, so it must be closed while RetroDrive edits it. Games without an entry still show (by file name).
- **Favorites playlist (2026-11-07, checked on the owner's RetroBat and in batocera-emulationstation's `FavoriteMusicManager.cpp`):** `emulationstation\.emulationstation\music\favorites.m3u`, one line per song: `<full path with forward slashes>;<name>` (CRLF; name = file name without extension), e.g. `G:/RetroBat/emulationstation/.emulationstation/music/Backroom Shuffle.mp3;Backroom Shuffle`. Used when `audio.useFavoriteMusic` (bool) is on; RetroBat turns that off when the playlist is empty. Paths include the drive letter (RetroBat's own format), so a different drive letter needs the design applied again. RetroBat's menu labels: `audio.persystem` = *Only play system-specific music folder*, `audio.thememusics` = *Play system-specific music*; `MusicVolume` is a percentage (0-100) in RetroBat.
- **RetroBat themes (2026-11-06, checked on the owner's RetroBat 8.3.1.1, read only):** themes live in `emulationstation\.emulationstation\themes\<folder>` and the active one is the `ThemeSet` setting. Carbon (CC BY-NC-SA, by Fabrice Caruso, based on Rookervik's Carbon and Nils Bonenberger's Simple) is driven by `<variables>` in `theme.xml` (10 colors, `backgroundImage`); its `colorset` subset includes files that override those variables, and the first include applies when the user hasn't chosen one; fonts are `art/fonts/*.ttf`. Carbon is 1.1 GB (mostly per-system art).
- **RetroPie (RDS-023 step 1, 2026-11-07, `src-tauri/src/adapters/retropie.rs`; facts from RetroPie-Setup `platforms.cfg`, `lr-fbneo.sh`, `lr-mame.sh` and RetroPie-Docs `Transferring-Roms.md`):**
  - **Where games are:** `~/RetroPie/roms/<system>` on the Pi's Linux partition (not readable from Windows). From Windows: the Samba share `\\RETROPIE\roms`, whose root is the roms folder, or a USB stick with a `retropie` folder (transfer) or `retropie-mount` (USB ROM service), each with `roms\<system>` inside.
  - **Detection:** "Detected" needs at least 3 RetroPie system folders including one only RetroPie uses (`ports`, `coleco`, `fba`, `mame-libretro`, `atarilynx`, `sg-1000`, `videopac`, `wonderswan`, …); 3 generic ones → "Possible"; a drive with `retropie`/`retropie-mount` → points at it; a Raspberry Pi boot partition (`config.txt`, `cmdline.txt`, `start*.elf`/`bootcode.bin`) → explains where games go. RetroBat and Batocera folders are never claimed.
  - **Folder mapping:** RetroBat's, translated to `platforms.cfg` names: `atarilynx`, `atarijaguar`, `amiga`, `msx`, `segacd`, `sg-1000`, `coleco`, `videopac`, `wonderswan(color)`; PC Engine CD and SuperGrafx in `pcengine`; no RetroPie folder for Amiga CD32, Neo Geo CD, GX4000, Supervision, Naomi, Atomiswave. Arcade (and CPS): FinalBurn Neo → `fba`, MAME → `mame-libretro` (choose lr-mame on the Pi for current MAME sets).
  - **Layout:** `PlacementOptions.has_roms_folder` (set when the installation folder has `roms` inside) chooses `roms/<system>` or `<system>`; plans show the real prefix (`DeploymentPlan.systems_prefix`).
  - **Copying (step 2, 2026-11-07, owner go-ahead, docs/18 §26):** on, with the same copier as RetroBat and Batocera, to the roms share or a USB `retropie`/`retropie-mount` folder; the share gets the share id of ADR-046. The layout check *Copying* is OK for a USB folder and a warning for the share ("keep RetroPie on…; restart RetroPie or EmulationStation afterwards to see new games").
  - **Sync, art and details (step 3, 2026-11-07, ADR-052, docs/18 §27):** the RetroPie card has **Sync**. RetroPie's EmulationStation uses `<rom folder>/gamelist.xml` if it exists, otherwise `~/.emulationstation/gamelists/<system>/gamelist.xml` (`SystemData::getGamelistPath`; the home folder isn't shared, so Windows can't see it). Owner's choice: only lists already in rom folders are filled in; for systems without one the art check lists them and offers *Also create game lists for … systems* (off by default, with a warning); art added after a copy never creates lists. Images go to `<system>\images` (no `roms` level on the share). The result says to restart RetroPie (or EmulationStation).
  - **Settings (step 4, 2026-11-07, ADR-053, docs/18 §28):** RetroPie shares `configs` (`/opt/retropie/configs`) beside `roms` (`samba.sh`). Each `configs\<system>\emulators.cfg` lists installed emulators (`<id> = "<command>"`) and `default = "<id>"` (`addEmulator`, `helpers.sh`). Customize offers the default emulator per system with games, from the ids in that file; only the `default` line changes. Needs the installation added by its network share (`\\<host>\roms` → `\\<host>\configs`); a USB stick has no settings. Journal and backups are on the configs share (`.retrodrive\backup`).
- **ES-DE (RDS-025 step 1, 2026-11-07, `src-tauri/src/adapters/esde.rs`; facts from ES-DE's source and user guide on GitLab):**
  - **Where games are:** a ROMs folder with one folder per system (`%ROMPATH%\<system>` in `resources/systems/windows/es_systems.xml`); default `%USERPROFILE%\ROMs`, or the `ROMDirectory` setting in `ES-DE\settings\es_settings.xml`. ES-DE writes `systems.txt` in the ROMs folder and `systeminfo.txt` in each system folder when it creates them.
  - **Detection:** ES-DE's markers plus a system folder → "Detected"; 3 system folders without markers → "Possible"; ES-DE's data folder → points at the ROMs folder. RetroBat and Batocera folders are never claimed, and the RetroPie adapter steps aside when ES-DE's markers are present (ES-DE creates RetroPie-style folder names too).
  - **Folder mapping:** RetroBat's names, except `atarilynx`, `atarijaguar`, `amiga`, `sg-1000`, `wonderswan`, `wonderswancolor`; arcade to `mame` or `fbneo`, CPS to `cps1/2/3` (all ES-DE systems). Plans show folders at the top of the ROMs folder.
  - **Copying and Sync (step 2, 2026-11-07, owner go-ahead "go", docs/18 §30):** on, with the reviewed copier (a normal Windows folder: local, USB or NAS; a NAS path gets the share id). The ES-DE card has **Sync**; art isn't added yet (ES-DE keeps game lists and media in its own data folder, next step). RetroDrive's copy records go in the ROMs folder's `.retrodrive` folder, which ES-DE doesn't load (it only loads folders named after its systems).
  - **Portable ES-DE (2026-11-07, checked on the owner's `G:\ES-DE`):** `ES-DE.exe` + `portable.txt`, data in `ES-DE\`, games in `ROMs\` (empty at first; a blank `ROMDirectory` means this folder) and every system folder in `ROMs_ALL\` (to copy from). The `ROMs` folder next to `ES-DE.exe` is "Detected" even while empty (RetroDrive creates the system folders it copies into); choosing the program folder, `ROMs_ALL` or the data folder points at it.
  - **Real test (2026-11-07, owner's go-ahead "OK, Atari 2600"):** in a test copy of RetroDrive on a copy of the owner's catalog, `G:\ES-DE\ROMs` was added and Atari 2600 copied: 1,576 games verified on the exFAT drive (1,754 other copies of the same games not copied), then Sync confirmed 1,576 already there. ES-DE showed Atari 2600 with 1,576 games (owner's screenshot). RetroBat untouched.
  - **Art and details (step 3, 2026-11-07, ADR-057, docs/18 §32):** ES-DE's data folder is found next to a portable `ES-DE.exe` (`ES-DE\`) or as `%USERPROFILE%\ES-DE` when its `ROMDirectory` points at this ROMs folder. Details go into `<data>\gamelists\<system>\gamelist.xml` (only what's missing; no image tags); pictures are copied to `downloaded_media\<system>\covers` (box art or main image) and `marquees` (logos) named after the game's path without its extension (`MediaDirectory` setting respected); a picture ES-DE already has (`.png`/`.jpg`/`.jpeg`) is kept. Refused while `ES-DE.exe` runs (it saves its lists when it closes). Nothing is written in the ROMs folder.
- **Recalbox/Lakka and others:** later adapters (RDS-025).

## Installation wizard (later, gated release)
1. Choose target device and scenario (bootable OS, portable Windows, cabinet, Pi/handheld when supported).
2. Identify exact hardware architecture and compatibility.
3. Select appropriate upstream distribution/version.
4. Download from verified official source; verify checksum and/or signature against authenticated upstream publication.
5. Select physical target; show model, serial when safe, capacity, partitions and wipe warning.
6. Protect boot/system and active-data disks; refuse ambiguous or unsafe targets.
7. Require explicit disk-specific confirmation for destructive operations; provide backup guidance.
8. Apply platform-specific imaging or install method; verify resulting image/layout.
9. Produce first-boot steps and validation summary.

## Imaging safety invariants
- Cannot write to running OS disk or selected source disk.
- Refuse unexpected capacity, identity or mount changes between selection and execution.
- No silent partition deletion; no default target selected for destructive action.
- Validate download trust and full image before use.
- No arbitrary shell invoked via untrusted image metadata.
- Interrupted imaging yields 'potentially unusable destination' with recovery instructions, not 'success'.
- Separate elevated helper restricted to allowlisted imaging operations; build/test only after an explicit architectural review.
