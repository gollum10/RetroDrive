# Theme Studio security boundaries

**Image presentation boundary:** only existing authorized bounded PNG data URLs reach intrinsic dimension decoding. Dimensions are checked against codec limits and stale load callbacks ignored. Crop fields use finite bounded percentages; unsupported objects stay inert/read-only. An explicit source-region SVG clip prevents off-crop pixels appearing in Fit margins. No external URLs, new raw image formats, IPC, filesystem writes or permissions are added.

**PNG workflow boundary:** selected browser File bytes (max 16 MiB) enter a bounded base64 command on a worker; a try-lock limits native image work to one operation. SQLite transactional/no-update content-addressed storage avoids adding source/destination path authority and is capped at 256 MiB/2,000 blobs. Preview requires a saved source declaration, byte/hash agreement and PNG signature, returning PNG-only data. Frontend guards URL MIME/encoding/size and limits each scene cache to eight images/32 MiB. Existing CSP suffices; no arbitrary URI/file protocol is added. See [review](image-import.md#managed-catalog-import-and-preview).

**PNG boundary:** pure image_import rejects bad framing/CRC, animation, oversized input/dimensions and failed pixel decoding; it ignores compressed text/profile metadata and writes a fresh RGBA8 container in memory. No path/URL/IPC/filesystem authority is exposed. Explicit budgets are not a hard CPU/RSS sandbox. Managed store/link/race/no-replace tests and authorized preview serving remain prerequisites for actual UI import. See [limits](image-import.md).

Canvas preview renders allowlisted SVG text/rectangles using finite validated geometry, strict hex colors, bounded text/font sizes and a system font. It never spreads arbitrary style objects, evaluates bindings/scripts, renders supplied SVG, or loads asset paths/URLs. Unknown text/color/font expressions and nested/future nodes are retained read-only. History is bounded and local to a session; no new filesystem/IPC authority. Native pointer/keyboard interaction QA remains pending. [Details](canvas.md).

Native close fix grants core:window:allow-destroy to the existing main-window capability because the SDK's awaited close handler needs that command after persistence succeeds. It adds no arbitrary filesystem, shell or installation access. The handler never re-requests close; failed saves still cancel. The permission change requires a native restart. Regression tests stub native IPC and never destroy the user's running window or access their catalog.

PR 4 adds pure capability analysis and read-only detection. Callers cannot supply a verified engine profile or writable path through IPC. No production adapter is enabled; reports always disable export/deploy, including truncated/unknown/unsupported cases. Detection reuses presence/layout reads and never claims a share ID or updates installation records. Exact-profile fixtures are synthetic only. [Evidence](target-matrix.md).

PR 3 adds only the separate UI and a read-only validation command; source is validated before editable rendering. Overview renders labels, not arbitrary styles, scripts, SVG or external media. App/native leave guards retain pending edits on persistence failure; no target-write authority is added. [Workspace](workspace.md).

PR 2 adds only managed-catalog writes via bounded validated source and transactional/revision-checked project commands. No caller may select a database or writable target path. Checkpoint/draft recovery and additive migration are tested in disposable catalogs. Uneditable source is returned intact rather than replaced with defaults. No installation, package, asset or game file is touched; [storage contract](persistence.md). The no-IPC statement below applies to PR 1 only. Work in this same isolated checkout now uses branch `feature/theme-studio-persistence`; PR 1 was merged by the owner, so PR 2 targets main directly.

PR 1 adds pure JSON domain code. No Tauri commands, schema migrations, installed-theme writers, extractors or rendering code. Existing Customize and disk services are unchanged.

Untrusted source enters bounded parse_project: version/shape, duplicate keys, size/depth/counts, absolute paths, graph/reference checks, typed bindings, finite layout and asset declarations. Unknown data stays inert. Constructed models need validate_project before persistence/serialization. No path fetches resources, evaluates expressions, renders SVG or executes theme content.

Later boundaries require separate tests: actual asset bytes/hash/codec/SVG checks; archive traversal/links/bomb/payload limits; safe preview properties; explicit compiler reporting of unsupported data; sharing privacy/license audit. Structural validation does not replace these gates.

Installation requires a dedicated scoped safety review and owner-authorized plan before target mutations. Reuse identity checks, stale-review SHA protection, no-replace renames, read-back verification, retained backups and journaled recovery where appropriate. Existing docs/18 authorization is not blanket approval for a new deployment service. No automatic boot/system writes or deletion of working themes/backups.

Development is isolated in .worktrees/theme-studio on feature/theme-studio-schema. The original checkout's branch and uncommitted planning documents, and the existing RetroInstaller-wip checkout, are preserved. A Git-local info/exclude entry hides .worktrees; no tracked ignore rule changes. Build outputs are isolated; Git refs/object storage remain shared. Do not reset/switch/force-push another checkout's branch.
