# 13 | Product Decisions and Open Questions

**Image preview lifecycle:** deduplicate concurrent effect requests by full project/asset/hash/length identity without weakening native saved-declaration authorization. Retry image_busy only (100/200/300ms delays, four attempts total); permanent errors remain visible and manual retry is available. Discard stale effects and cached data not represented by current declarations.

**Theme image storage decision:** use normalized immutable catalog blobs rather than a new loose-file tree. This fits SQLite authoritative local state and eliminates new destination-path/link races. Portable source retains only assets/images/<hash>.png and metadata. Preview authorizes saved declarations; API has no filesystem-path parameter. Undo removes source attachment, retaining deduplicated bytes for recovery. Quotas bound retained content until separately reviewed cleanup exists.

**Theme Studio first raster boundary:** static PNG only, normalized to RGBA8 and hashed after re-encoding. Original metadata/profiles and animation are not retained; 16-bit samples reduce to eight bits. Explicit input/pixel/scratch/output limits are not a process sandbox. No file reads/writes or IPC are enabled by this increment.

**Theme Studio layer-state semantics:** node.editor.locked/hidden are additive portable editor preferences. Hiding changes only editor preview, not native output visibility; conditional/native visibility remains separate future work. Locking protects content; flag controls remain available to unlock/show. Ordering cannot move a protected layer or cross protected layers. Unknown editor payloads remain read-only and unmodified.

**Theme Studio canvas aids:** grid/snapping preferences are transient workspace aids, not universal document content. Canvas alignment takes precedence over grid rounding when within six screen pixels. Resize snaps local width/height, while arrow keys retain exact steps. Other-layer snapping and custom guides remain later work.

**Canvas first slice (2026-11-08):** original top-level text/panels only; completed drag commits one operation, cancellation leaves source untouched. Preserve coordinate units/future fields. Use bounded session JSON history with grouped edits; undo/redo persists as drafts and never rolls back explicit checkpoints or target settings. Preview interprets only safe SVG primitives/hex colors/system font, with unsupported source properties read-only. No rendering engine or dependencies added.

**Project copy UX (2026-11-08):** distinguish editing the current project's name from naming a new copy. Save As temporarily disables original metadata controls and requires explicit copy confirmation; cancelling creates nothing. Numbered display-name suggestions replace repeated copy-copy labels without renaming existing projects or adding a database uniqueness rule. No change to source format, revision/persistence semantics or installation writes.

**Native close regression (2026-11-08):** use Tauri's awaited original close handler and explicit main-window allow-destroy capability. Do not recursively request close or add broad window/default permissions. Persistence failure continues to cancel closing. Scope is window lifecycle only; no storage permission expansion or target mutation.

**Theme capability evidence (2026-11-08):** app release and engine compatibility are separate. Only an evidenced exact family/fork/engine/OS/architecture/format rule may claim an outcome. Unknown or ambiguous matches fail closed; conversion/degradation needs fallback/consent. No real adapters are registered yet. Synthetic tests never become shipped native support. [Matrix](theme-studio/target-matrix.md).

**Theme Studio editor lifecycle (2026-11-08):** one serialized session owns revisions and local edits. Native/app navigation flushes before leaving; failures retain the session. Recovery/discard is explicit. Save As copies the current local source via create rather than silently using a stored checkpoint. Native rendering/support remains unverified. No new framework or dependencies.

**Theme Studio working-state decision (2026-11-08, PR 2):** SQLite v27 holds separate checkpoints/drafts and monotonic revision tokens. Recovery reads a draft without promoting it; explicit save checkpoints it, discard restores the saved name, and rename changes metadata in both sources while retaining unfinished content. Save As explicitly selects checkpoint or draft and creates an independent identity. Raw source is returned unchanged on open, even when its schema is not editable. No retries overwrite concurrent edits. See [contract](theme-studio/persistence.md).

**Theme Studio contract decision (2026-11-08, owner-approved Option B):** universal portable JSON, SQLite authoritative local working state, explicit empty target intent (Universal / No Target Yet), and separate platform exporters. PR 1 uses a flat scene node arena with ordered child IDs and preserves unknown JSON fields inertly. Local paths/bindings stay outside portable source. Exact 1.0.0 schema only; future versions are refused without data replacement. No changes to legacy DesignSpec or catalog schema. See [contract](theme-studio/project-format.md) for validation limits and future boundaries.

| ADR-027 | (2026-11-05) Duplicates and unwanted files are handled by **leaving them out of the library** (a catalog mark), never by deleting files. Cleanup keeps one copy per duplicate group by a deterministic rule (present and connected, shortest path, then name) and shows a preview first | Owner decision: users choose what to keep so their drives don't fill with copies. RetroDrive never deletes files (AGENTS.md, docs/18); a reversible mark gives the same result for the library and for copies. A deterministic rule makes the preview and the cleanup agree. |
| ADR-026 | (2026-11-05) Recognize 49 systems by folder name (RetroBat's names plus common spellings and the owner's hack folders), keep shared disk-image extensions folder-only, treat `bios` folders and `[BIOS]` names as a separate **BIOS** system that is never placed or copied, and let rescans move a game to its newly recognized system | The owner's 60,558 Unclassified games were all in standard system folders; a snapshot check shows 60,554 now recognized and none newly rejected, so rescans won't mark files missing. BIOS files mixed with games were being counted (and could be placed) as games; RetroBat expects them in `bios\`, and copying BIOS files is a separate, legally sensitive feature (docs/16 §4). |
| ADR-025 | (2026-11-05) Box art comes only from the user's own files: `gamelist.xml` entries and folder conventions found during scans, or an image the user picks. RetroDrive stores image **locations**, never copies or caches images, and shows them through a custom `rdmedia` protocol that serves only images linked in the catalog | RetroDrive must not ship or distribute art (owner policy; docs/16 §7). The owner's library already holds Skraper art beside the ROMs (the "129,179 ignored files"), so linking at scan time gives art with no extra steps. A custom protocol keyed by game id avoids enabling general file access for the web view. Alternatives considered: copying art into app data (rejected: duplicates copyrighted files) and a thumbnail cache (deferred; would also be a copy). |
| ADR-024 | (2026-11-05) The owner's game catalog is imported as a **user-supplied reference catalog**, kept in separate tables and linked to games; names, details and genres only, **never art** (owner decision). Matching prefers exact No-Intro/MAME names, then MAME clone sets, then the same title on the same system, and never guesses between ambiguous titles. Bundling the catalog with RetroDrive is a separate, later decision (LEGAL-016) | Exact names are reliable (93% of the owner's arcade sets); titles fill most of the rest (SNES 13% → 72%). Keeping reference data separate preserves the library and any future hand edits. Artwork is copyrighted and the owner doesn't want it distributed. Some catalog sources carry conditions (Wikipedia text is CC BY-SA), so shipping the data needs review; importing one's own file for personal use doesn't. |
| ADR-022 | (2026-11-05) Arcade placement is a per-installation user choice (`mame` or `fbneo`, default none) stored on `installations` (schema v8) and passed to adapters as `PlacementOptions` (adapter contract **v2**). Only `.zip`/`.7z` archives are placed, unchanged; CHDs are not placed yet. RetroBat's version is read from `system\version.info` | The RetroBat Arcade Guide says romset versions must match the emulator, so guessing could send games to an emulator that can't run them. Per installation, because different drives may hold different sets. CHDs need a folder named after their zip, which the catalog doesn't link yet. The version file was found on a real 8.3.1.1 install (`RetroBat.exe` reports 8.3.0.0, which is misleading). |
| ADR-023 | (2026-11-05) RetroDrive is positioned for **personal use** of the user's own files. It will not offer to prepare drives or machines for others or for sale, and a OneSauce/RetroFE target waits for LEGAL-015 | The RetroBat installer license forbids selling pre-installed machines or drives and shipping RetroBat with copyrighted content; OneSauce builds ship BIOS files and are sold pre-loaded by third parties. Keeping RetroDrive a personal tool keeps it on the "manage a user-installed copy" side of docs/16 §5. |
| ADR-021 | (2026-11-05) The first writer (RDS-010) copies only from a re-validated plan (matching fingerprint, same volume, space measured), journals before writing, stages each file as `<name>.rdpart-<id>` created with `create_new`, verifies SHA-256 by reading back past the Windows cache, and commits with `MoveFileExW` **without** replace. It never deletes anything except its own temporary files. Partly copied games keep their verified files and a retry finishes them. The manifest lives in the catalog and as `.retrodrive/deployments/<id>.json` in the installation. Adapters stay read-only; copying is RetroDrive's own service | `std::fs::rename` silently replaces files on Windows, so a no-replace rename is the only safe commit. Keeping verified files avoids writing any delete code (owner decision). The manifest file travels with the drive (owner decision). A dedicated safety review (docs/18) and an independent code review (10 findings, all fixed) were done before merge, as AGENTS.md requires. `sha2` was added as a direct dependency; it was already shipped through Tauri. |
| ADR-020 | (2026-11-05) The deployment plan (RDS-009) is read-only and conservative: a same-name, same-size file counts as **already there** (contents are compared by the copier, RDS-010, not the plan); a different file is a **conflict kept by default**; links, folder clashes, case clashes, FAT size limits and paths outside the installation are **blocked**; a game takes its worst file action. Capacity keeps a reserve of max(1 GiB, 2%) plus room for the largest file, rounded to clusters. The plan returns a fingerprint the copier must match | Reading every same-size file on both drives would make planning take hours on big libraries; the copier verifies anyway. Partly copying a multi-disc game would leave it broken. Unknown free space is never reported as fitting (docs/08). The fingerprint lets RDS-010 detect that the drive or catalog changed after the user reviewed the plan. Replaced the placement-preview command, since the plan includes it. |
| ADR-019 | (2026-11-04) Adopt the legal assessment (docs/16) as a project constraint. Features that download, install or bundle third-party software, or fetch artwork or metadata, are **blocked** until the matching LEGAL item is resolved. CI enforces a dependency license allowlist (permissive plus MPL-2.0 with notices; copyleft and unknown licenses fail) | Legal risk comes from what the app bundles, downloads or represents (docs/16 §1). Building the gates in now is cheaper than retrofitting them. Names in docs/16 were updated to RetroDrive per ADR-017, with an editor's note. Affects docs/11 (gated items), 14 and 17, and CI. |

## Recommended, awaiting implementation validation
- Separate privileged helper for imaging, with hardened permissions.
- No sign-in requirement or default network telemetry.
- RetroBat ordinary-folder deployment before raw disk imaging.
- Metadata provider integration with licensing review.
